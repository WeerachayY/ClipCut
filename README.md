# ClipCut

PWA สำหรับตัดช่วงที่ไม่ต้องการออกจากวิดีโอ เช่น ช่วงรอเริ่ม ช่วงพัก หรือท้ายคลิปที่ลืมหยุดบันทึก
เหมาะกับวิดีโอที่มีคนพูดเป็นหลัก เช่น ประชุม อบรม สัมมนา คลาสเรียน หรือสัมภาษณ์
แอปใช้ transcript (ถ้ามี) ร่วมกับการวัดเสียงเงียบ เพื่อเสนอช่วงที่ควรตัด แล้วให้คนฟังรอยต่อก่อนยืนยัน

- **ประมวลผลในเครื่องทั้งหมด** วิดีโอและ transcript ไม่ถูกอัปโหลดไปไหน ไม่ใช้ AI
- **ตัดแบบไม่ encode ใหม่** คุณภาพเท่าต้นฉบับ เร็วราว 1 นาทีต่อวิดีโอ 500 MB (ไม่ขึ้นกับความยาว)
- **ต่อหลายไฟล์** ที่บันทึกต่อกันเป็นไฟล์เดียว และ **แบ่งไฟล์เดียวเป็นหลายตอน** ได้ในขั้นตอนเดียวกัน
- **บีบอัดให้เล็กลง** แบบ HandBrake (H.264) เป็นตัวเลือก (ทดลอง ช้ากว่ามาก)
- ใช้ได้ดีที่สุดบน **Edge หรือ Chrome บนคอมพิวเตอร์** (เปิดทั้งโฟลเดอร์และบันทึกผลกลับลงโฟลเดอร์ได้)

## วิธีใช้

1. **เลือกไฟล์** — กด “เปิดโฟลเดอร์” แล้วเลือกโฟลเดอร์ที่มีวิดีโอ .mp4 และ transcript (ถ้ามี)
   (หรือลากไฟล์มาวาง) แอปเรียงไฟล์วิดีโอตามชื่อ และเลือก transcript ให้อัตโนมัติ
2. **ตรวจไฟล์** — เช็คลำดับวิดีโอ (เลื่อนขึ้นลงได้) และ transcript ที่ใช้ ปรับเกณฑ์ได้ใน “ตั้งค่าการหาจุดตัด”
   แล้วกด “หาจุดตัด” (ครั้งแรกจะโหลดตัวประมวลผลวิดีโอราว 32 MB และวิเคราะห์เสียงราว 1 นาทีต่อชั่วโมง)
3. **ตรวจจุดตัด** — ทำงานแบบ “ผ่าแล้วเลือกชิ้น” เหมือนเครื่องมือ Razor/Blade ในโปรแกรมตัดต่อ
   - กด **มาร์กจุดตัด** (C) เพื่อผ่าวิดีโอที่ตำแหน่งเล่น จุดตัดแต่ละจุดแบ่งวิดีโอเป็นชิ้น
   - **คลิกชิ้น** บน timeline แล้วกด “ทิ้งชิ้นนี้” (หรือดับเบิลคลิกชิ้น) ชิ้นที่ทิ้งจะเป็นลายทางแดง
   - **คลิกที่หัวจุดตัด** เพื่อ “ต่อกลับ” (ชิ้นสองข้างรวมกันและถูกเก็บไว้เสมอ), “แยกเป็นไฟล์ใหม่ตรงนี้”, หรือขยับ ±1 วิ
     **ลากหัวจุดตัด** เพื่อขยับ (ดูดเข้าหาตำแหน่งเล่นเมื่อลากเข้าใกล้)
   - ช่วงที่แอปหาให้จะมาเป็นชิ้นที่ “แนะนำให้ทิ้ง” (กรอบแดง) หรือ “ควรเช็ค” (กรอบส้ม) กดทิ้งหรือเก็บทีละชิ้น
     หรือ “ทิ้งทุกชิ้นที่แนะนำ”
   - กด **ฟังรอยต่อ** เพื่อฟัง 5 วินาทีก่อนชิ้นที่ทิ้ง แล้วกระโดดไปฟัง 5 วินาทีหลังชิ้นนั้น (เหมือนไฟล์ผลลัพธ์)
   - เส้นประจาง ๆ ในชิ้นที่ทิ้งคือจุดที่แบบไม่บีบอัดจะกลับมาเล่นจริง (keyframe) แบบบีบอัดตัดตรงจุดเป๊ะ
   - แท็บ **Transcript และหมุดเวลา**: ถ้าเวลาใน transcript ไม่ตรงกับเสียง ให้เล่นวิดีโอแล้วกดหมุดของบรรทัดนั้น
     ตอนได้ยินประโยคเริ่ม ปักได้หลายจุด (โหมด “ค่อย ๆ ไล่เวลา” สำหรับเวลาคลาดสะสม,
     “กระโดดที่หมุด” สำหรับการบันทึกที่หยุดแล้วเริ่มใหม่) หรือกด “หาหมุดจากจุดที่เสียงกลับมา”
   - ติ๊ก “เล่นแบบผลลัพธ์” เพื่อดูวิดีโอโดยข้ามช่วงที่ตัดแล้ว
4. **ส่งออก** — เลือก “ไม่บีบอัด” (แนะนำ) หรือ “บีบอัดไฟล์ให้เล็กลง” แล้วกดส่งออก
   ไฟล์จะถูกบันทึกในโฟลเดอร์ `output/` ข้างไฟล์ต้นฉบับ พร้อมไฟล์ `_สรุปการตัด.txt`

งานที่ทำค้างจะถูกบันทึกเป็น `clipcut.project.json` ในโฟลเดอร์งานอัตโนมัติ เปิดโฟลเดอร์เดิมอีกครั้งเพื่อทำต่อได้

### ปุ่มลัด (หน้าตรวจจุดตัด)

| Home / End | ไปต้น / ท้ายวิดีโอ | เหมือนกัน |
| ↑ / ↓ | ไปจุดตัดก่อนหน้า / ถัดไป | เหมือนกัน (edit point) |

## รูปแบบไฟล์ที่รองรับ

| ประเภท | รูปแบบ |
|---|---|
| วิดีโอ | .mp4 / .m4v / .mov ที่ browser เล่นได้ (เช่น H.264 + AAC ซึ่งเป็นค่าปกติของโปรแกรมบันทึกส่วนใหญ่) |
| Transcript | Word (.docx) หรือ .txt ที่เขียนบรรทัดละ `[00:01:34] ชื่อ: ข้อความ` (รูปแบบที่ bot จดบันทึกหลายตัวใช้) · คำบรรยาย .vtt / .srt (เช่น จาก Teams, Zoom, YouTube) |

ไม่มี transcript ก็ใช้ได้ แอปจะเสนอเฉพาะช่วงที่เสียงเงียบนาน

## ข้อจำกัดที่ควรรู้

- **แบบไม่บีบอัด จุดตัดถูกปรับตาม keyframe** แอปจะเลื่อนจุดที่วิดีโอกลับมาเล่นให้ *เร็วขึ้น* ไปยัง keyframe ก่อนหน้า
  (ปกติ 1–4 วินาที) จึงอาจเหลือส่วนที่ทิ้งติดมานิดหน่อย แต่ไม่ทำให้เนื้อหาหาย และชิ้นที่สั้นกว่าระยะ keyframe จะตัดไม่ได้
  แอปแสดงจุดจริงให้ดูทุกชิ้น ถ้าต้องการตัดเป๊ะให้ใช้แบบบีบอัด
- **ที่รอยต่ออาจมีภาพกระตุก 1–2 เฟรม** ถ้าวิดีโอใช้ B-frame เป็นข้อจำกัดของการตัดแบบไม่ encode ใหม่
- **ไฟล์ผลลัพธ์แต่ละไฟล์ต้องเล็กกว่าราว 1.9 GB** (เพดานหน่วยความจำของ browser) ถ้าใหญ่กว่านั้นให้เพิ่มจุดแบ่งไฟล์
  วิดีโอที่บันทึกการพูดหรือหน้าจอมักเล็กกว่านี้มาก
- **การต่อหลายไฟล์แบบไม่บีบอัด** ต้องเป็นไฟล์ที่บันทึกด้วยการตั้งค่าเดียวกัน แอปตรวจและเตือนให้
- **แบบบีบอัด** ตัดตรงจุดเป๊ะ แต่ใช้ CPU ใน browser ช้าราวเวลาจริงหรือมากกว่า เหมาะกับวิดีโอสั้น หรือปล่อยทิ้งไว้

## Deploy ขึ้น GitHub Pages

ไม่มีขั้นตอน build ไฟล์ใน repo คือเว็บที่ใช้จริง

1. สร้าง repo ใหม่บน GitHub แล้ว push ทั้งโฟลเดอร์นี้ขึ้นไป
   ```bash
   git init && git add . && git commit -m "ClipCut"
   git branch -M main
   git remote add origin https://github.com/<user>/clipcut.git
   git push -u origin main
   ```
   (ไฟล์ `vendor/core/ffmpeg-core.wasm` ขนาด ~32 MB push ได้ตามปกติ ไม่ต้องใช้ Git LFS)
2. ใน repo ไปที่ **Settings → Pages** เลือก Source = *Deploy from a branch*, Branch = `main`, โฟลเดอร์ `/ (root)`
3. รอสักครู่ แล้วเปิด `https://<user>.github.io/clipcut/`
4. ใน Edge/Chrome กดไอคอนติดตั้งในแถบที่อยู่ เพื่อใช้เป็นแอปและใช้ offline ได้

เมื่อแก้โค้ดแล้ว push ใหม่ ผู้ใช้จะได้เวอร์ชันใหม่ในการเปิดครั้งถัดไป

**ออกเวอร์ชันใหม่:** เปลี่ยนเลขให้ตรงกันใน `js/version.js`, `package.json` และ `VERSION` ใน `sw.js`
(test จะเตือนถ้าไม่ตรง) แล้วเขียนสิ่งที่เปลี่ยนไว้ใน `CHANGELOG.md` เลขเวอร์ชันแสดงข้างโลโก้ในแอป

### ทดลองบนเครื่องตัวเอง

ต้องเปิดผ่าน http server (เปิดไฟล์ index.html ตรง ๆ ไม่ได้ เพราะใช้ ES modules และ service worker)

```bash
python3 -m http.server 8080
# แล้วเปิด http://localhost:8080
```

js/main.js                                ตัวควบคุมแอป: โหลดไฟล์, วิเคราะห์, บันทึกงาน, สลับหน้า
js/version.js                             เลขเวอร์ชันของแอป
js/core/                                  ตรรกะล้วน ไม่แตะ DOM ทดสอบได้ด้วย Node
  timeline.js    ต่อหลายไฟล์เป็น timeline เดียว + หา keyframe
  timemap.js     หมุดเวลา transcript ↔ วิดีโอ (linear / step)
  suggest.js     รวมผลจากตัวหาจุดตัดหลายตัวเป็นข้อเสนอพร้อมระดับความมั่นใจ
  analysis.js    เรียกตัวหาจุดตัดทุกตัว + เสนอหมุดอัตโนมัติ
  plan.js        แปลงการตัดสินใจเป็นแผนส่งออก (concat inpoint/outpoint)
  cuts.js        จุดตัดและชิ้น: มาร์ก, ต่อกลับ, ขยับ, แยกไฟล์, ทิ้ง/เก็บ, รับข้อเสนออัตโนมัติ
  registry.js    ทะเบียนปลั๊กอิน (ดู docs/EXTENDING.md)
  store.js       state ของแอป + บันทึก/โหลดไฟล์งาน
js/plugins/                               ฟีเจอร์ที่ถอด-ใส่ได้ ลงทะเบียนใน plugins/index.js
  transcript/    ตัวอ่าน transcript (.docx, .vtt/.srt, .txt)
  detectors/     ตัวหาจุดตัด (ช่องว่างใน transcript, คำบอกเบรก, เสียงเงียบ)
  export/        วิธีส่งออก (ไม่บีบอัด, บีบอัด H.264)
js/media/                                 งานที่แตะวิดีโอ: ffmpeg.wasm, อ่าน keyframe, วิเคราะห์เสียง, ส่งออก
js/io/                                    เปิดโฟลเดอร์/ไฟล์, อ่าน zip (.docx), บันทึกไฟล์
js/ui/                                    หน้าจอทั้ง 4 ขั้น, timeline, player
icons/                                    icon.svg (ต้นฉบับ), favicon.svg (แบบเรียบสำหรับขนาดเล็ก), PNG สำหรับติดตั้งแอป
vendor/                                   ffmpeg.wasm และฟอนต์ (ดู vendor/README.md)
tests/                                    ทดสอบด้วย `node --test tests/*.test.mjs`

## เพิ่มฟีเจอร์

ฟีเจอร์ส่วนใหญ่เพิ่มได้ด้วยไฟล์เดียว + บรรทัดเดียวใน `js/plugins/index.js`
ดูคู่มือและตัวอย่างใน [docs/EXTENDING.md](docs/EXTENDING.md) เช่น

- วิธีส่งออกแบบใหม่ (ปรับเสียงให้ดังเท่ากัน, แปลงเป็นเสียงอย่างเดียว .m4a, ใส่ chapter)
- ตัวหาจุดตัดแบบใหม่ (จอค้างหน้าสไลด์ “Break”, ช่วงที่ภาพนิ่งนาน)
- ตัวอ่าน transcript รูปแบบอื่น

## ทดสอบ

```bash
node --test tests/*.test.mjs
```

- `tests/core.test.mjs` ทดสอบตรรกะทั้งหมด (timeline, หมุดเวลา, แผนตัด, ตัวอ่าน transcript, การรวมข้อเสนอ)
- `tests/ffmpeg-native.test.mjs` รันคำสั่ง ffmpeg แบบเดียวกับที่แอปสร้าง กับ ffmpeg บนเครื่อง แล้วตรวจความยาวไฟล์ผลลัพธ์
  (ข้ามอัตโนมัติถ้าไม่มี ffmpeg)
